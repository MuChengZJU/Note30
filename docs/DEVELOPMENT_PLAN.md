# Note30 - AI 辅助开发计划

本计划将整个 App 的开发过程分解为四个清晰的、循序渐进的里程碑。我们将采用 AI 辅助编程的方式，专注地、一次一个地完成每个任务，直至应用功能完整。

---

## 里程碑 1: 项目基础与核心数据模型 (预计用时: 1-2 小时)

**目标**: 搭建一个可运行的、结构清晰的空项目，并定义好数据的存储方式。

-   [ ] **任务 1.1: 初始化安卓项目**
    -   [ ] 创建一个新的 Android Studio 项目。
    -   [ ] 配置项目，使用 Kotlin 语言和 Jetpack Compose UI 框架。
    -   [ ] 设置 App 的名称、图标和主题颜色。

-   [ ] **任务 1.2: 引入核心依赖**
    -   [ ] 在 `build.gradle.kts` 文件中，添加 `ViewModel`, `Room`, `Navigation Compose`, 和 `Kotlin Coroutines` 的依赖。

-   [ ] **任务 1.3: 定义数据模型 (Room)**
    -   [ ] 创建 `Record` 数据实体 (Entity)，包含 `id`, `timestamp`, `efficiency`, `mood`, `content` 等字段。
    -   [ ] 创建 `RecordDao` 数据访问对象 (DAO) 接口，定义增、查等数据库操作。
    -   [ ] 创建 `AppDatabase` 数据库抽象类，完成 Room 数据库的初始化配置。

-   [ ] **任务 1.4: 创建基础 UI 占位符**
    -   [ ] 创建两个空的 Composable 屏幕：`RecordScreen` 和 `HistoryScreen`。
    -   [ ] 配置 `Navigation Compose`，实现这两个屏幕之间的基础跳转。
    -   [ ] 搭建主界面的底部 Tab 导航栏。

---

## 里程碑 2: 核心记录循环的实现 (预计用时: 2-3 小时)

**目标**: 实现 App 的核心功能——让用户能够输入、保存并立即看到他们的记录。

-   [ ] **任务 2.1: 构建记录界面 (RecordScreen)**
    -   [ ] 设计并实现文本输入框、效率评级（数字选择）、情绪标签（可选词语）。
    -   [ ] 创建一个“保存”按钮。

-   [ ] **任务 2.2: 创建 ViewModel**
    -   [ ] 创建 `RecordViewModel`，用于处理 `RecordScreen` 的业务逻辑。
    -   [ ] 实现一个 `saveRecord` 函数，用于接收 UI 层的输入，并调用 DAO 将 `Record` 对象存入数据库。

-   [ ] **任务 2.3: 实现 UI 与逻辑的连接**
    -   [ ] 在 `RecordScreen` 中，将用户的输入状态与 `RecordViewModel` 绑定。
    -   [ ] 点击“保存”按钮后，调用 `saveRecord` 函数。
    -   [ ] (可选) 保存成功后，可以弹出一个 Toast 或 Snackbar 提示用户。

---

## 里程碑 3: 历史回顾与导出功能 (预计用时: 3-4 小时)

**目标**: 让用户能够查看他们所有历史记录，并能以 Markdown 格式导出。

-   [ ] **任务 3.1: 构建历史记录列表 (HistoryScreen)**
    -   [ ] 创建 `HistoryViewModel`，负责从数据库查询所有的 `Record` 记录，并按时间倒序排列。
    -   [ ] 在 `HistoryScreen` 中，以时间线 (Timeline) 的形式，将记录列表展示出来。
    -   [ ] 实现“时间线视图”和“日期列表视图”的切换功能。

-   [ ] **任务 3.2: 实现 Markdown 导出逻辑**
    -   [ ] 在 `HistoryViewModel` 中，创建一个 `exportToMarkdown` 函数。
    -   [ ] 此函数接收一个日期范围，查询对应的记录，并将其格式化为 PRD 中定义的 Markdown 字符串。

-   [ ] **任务 3.3: 实现导出 UI 与操作**
    -   [ ] 在 `HistoryScreen` 的右上角，添导出按钮。
    -   [ ] 点击按钮后，弹出日期选择器，允许用户选择“今天”或日期范围。
    -   [ ] 用户确认后，调用 `exportToMarkdown` 函数，并提供“复制到剪贴板”和“分享”两个选项。

---

## 里程碑 4: 后台服务与最终完善 (预计用时: 2-3 小时)

**目标**: 实现后台的定时提醒功能，处理特殊场景，并对 App 进行全面的测试和优化。

-   [ ] **任务 4.1: 实现后台定时提醒**
    -   [ ] 使用 `WorkManager` 或 `AlarmManager` 创建一个每 30 分钟触发一次的后台任务。
    -   [ ] 任务触发时，发送系统通知。
    -   [ ] 实现 3 分钟后的二次提醒逻辑。

-   [ ] **任务 4.2: 实现暂停与恢复功能**
    -   [ ] 在 `RecordScreen` 添加一个“暂停/恢复”按钮。
    -   [ ] 实现“暂停后总结”的逻辑：恢复时，弹窗要求用户对整个暂停时段进行一次性记录。

-   [ ] **任务 4.3: 全面测试与 UI 优化**
    -   [ ] 测试所有功能，包括边界情况（如无记录时、暂停超过一天等）。
    -   [ ] 优化 UI 细节、动画效果和整体流畅度。
    -   [ ] 准备 App 的最终图标和发布构建。
